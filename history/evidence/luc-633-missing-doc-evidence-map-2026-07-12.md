## Repair Rules

| Rule                              | Use when                                                                                                                           | Output                                                                                                                                                         |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Real docs gap                     | Runtime/product behavior, auth/security gate, exchange credential behavior, trading decision behavior, dashboard-visible behavior. | Add the narrowest module doc entry and `documentation-links.csv`; use `scanner-overrides.json` only when the inferred graph does not connect the doc relation. |
| Proof-link gap misread as doc gap | Row already has docs but lacks verified executable proof.                                                                          | Route to Test Automation Engineer / QA Regression Lead with `priority-test-links.csv` or entity verification work, not docs expansion.                         |
| Test-helper mapping noise         | Row path is under `*.test.ts`, e2e setup helper, fixture, request helper, env restore helper, or generated test utility.           | Prefer scanner noise classification or a short testing-doc link. Do not inflate product docs with test-only implementation details.                            |
| Cross-module auth-gated helper    | Account access flow appears because a bot/backtest/order helper requires user ownership/session checks.                            | Document in the owning module doc, with an auth-gate note; do not force everything into `api-auth.md`.                                                         |
